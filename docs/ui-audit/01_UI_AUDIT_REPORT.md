## Round 3: responsive grids, buttons, Tasks cards and scrolling tables (owner 07/11 17:30)

What the owner asked for and what was done is in 05_RESPONSIVE_CHECKS.md, with the result for every screen at five sizes. In short:

- **Card grids.** Every number-card grid (`.ui-kpis`, Reports cards) uses one rule set: phone 2 per row (Owner money 1), tablet 3 per row (Owner money 2), desktop as before. Cards in one row share a height; labels stay within 2 lines; on a phone the icon is hidden and the value scales with the width.
- **Buttons.** Plain buttons are outline buttons as in design v81 (Paper, dark edge, bold words); only the main action of an area is filled. The chosen part of a switch is the selected-card look. This replaces DL-107 part (2)'s light-green fill; the "never like a text box" rule holds through the dark edge and bold words (TEST-FE-1076 updated). The decision log entry goes through another thread.
- **Home Tasks.** Four cards (Overdue · Today · This week · Later) with the count and one line each; the Overdue count is red above 0; one list open at a time under the cards; the open card in the URL (`#/home?tasks=…`); Overdue opens by itself when it has items (TEST-FE-929, 930, 1915).
- **List pages.** `shell/tableFit.ts`: on screens at least 1024 px wide and 700 px tall the page fits the screen and only the main table scrolls in its own area with sticky headings and the pagination at its bottom; under 1000 px tall the page uses a tighter look; phones and short screens scroll normally with sticky headings (not when the table scrolls sideways: browser limit); Back returns to the same place in the table (TEST-FE-1916).
- **Checked, not fixed (on purpose):** fewer than 8 rows at 1366 × 768 on pages with 2- or 3-line rows or tall blocks above the list (open question 12); grouped pages scroll normally; Tasks 4 in a row on a tablet; notes up to 3 lines; empty room under a short table.

## Open questions

1. **Earlier forms, Settings and Users and access.** Each earlier form was checked against the rebuilt screens. They stay for now because some actions exist only there:
   - Users and access: role bundles (create and assign), administrative account recovery and the full list of access changes. The rebuilt Roles section edits roles but not bundles. Proposal: move these into Roles and History in a later step.
   - Settings › Utility rates: confirming the riel exchange rate. No rebuilt screen does it yet.
   - Settings › General: the earlier form also opens the Property ("Load business configuration") when none is open. The rest repeats the General tab. It can go once the app opens the one Property by itself in every case.
   - Payments, Invoices, Utilities, Leases, Notices, Move-outs: earlier forms are checked in their own module batch.
2. **Discard question on forms.** Add/Edit forms open as a drawer. The "Discard your changes?" question is on only where a form's Close just closes. Money windows keep their own close rules (DL-112), so they do not get it.
3. **Customer Latest Receipts** come from the Customer's ledger lines (Payment received), newest first, up to 1,000. The line shows the payment number, the payment day and the amount, and opens the Receipt. A reversed payment still shows, with its reversal in the full statement.
4. **Top-bar search** finds Customers and Units. Invoice, Receipt and Lease numbers are not searched: the server has no number search for them yet. Adding one is a server change, so it waits for an OK.
5. **Owner money "Spent this month"** adds the expense lines 5000 to 6999 of Budget vs actual. Profit this year is the "Profit (or loss)" line, year to date, of Profit and loss.
6. **Inspections menu (Joint Inspection, Unit Check) is not built yet.** The server has no list of inspections for a Property: Move-out inspections are read one Lease at a time, and Unit Checks are saved only by the Staff bot with no read route. A menu over them needs a new server read. That is more than a layout change, so it waits for an OK. Proposal: one read route "inspections of a Property" (Move-out inspections and Unit Checks, newest first), then the menu with two tabs.
7. **Early check-out money (owner rule 07/11 10:04, from the Database v1.2 review thread).** Unused nights stay paid; there is no money back by itself. Only the Owner, a Manager or a person with the credit right may give Credit for unused nights, with a reason, the same way as a late cancel. The "Check out early" window now says this. Decided: DL-200, added in a separate docs change by the Database v1.2 review thread.
8. **Server detail after an error.** A few messages (Ledger, Employees and payroll, Settings users) still add the server's own detail after the plain sentence, for example "This could not be saved: Enter a reason". Most server details are already plain English; Khmer screens show the Khmer words for known codes (V1-061). Hiding the detail completely needs a list of each module's error codes in the screens. Proposal: do it module by module in a later step, so a useful reason is never lost.
9. **Paid on time card and Birthdays (Home, Customers).** The design shows a "Paid on time" card (Invoices fully paid by their Due Date, last 12 months, from 04_GLOSSARY.md) and a Birthdays card and tab. Both need a server read: a new report for Paid on time, and Customer birth dates for Birthdays (the Customer record has no birth date today). Proposal: add both reads in the next server step, then the cards.
10. **Collapse menu.** Closed: the owner answered on 08/11/2026 (section D) and the side menu was built in round 6b (Collapse menu, folding groups, "⌄" sub-items, user card with the role, drawer, keyboard). See 02, round 6b.
11. **Number search in the top bar.** "Search Invoice, Receipt, Customer or Unit" is the placeholder, as in the design, but Invoice and Receipt numbers cannot be searched until the server has a number search (open question 4). When a person types a number such as INV260001, the search says so and points to the Invoices and Payments filters.
12. **One-line table rows (owner's "at least 8 rows" check).** At 1366 × 768 a list page whose rows carry two or three lines (name and phone, request and customer, status and note) shows 4 to 7 rows, because the top bar, tabs, title, number cards and filters take the rest of a 768 px screen. Proposal: one line per row on list pages (the second line moves to the record page or to a hover title), which gives 8 or more rows at 1366 × 768 on every list page. This changes what a row shows, so it waits for the owner's OK. Until then those pages keep their rows and the counts are listed in 05_RESPONSIVE_CHECKS.md.
13. **Print Lease: waiting for the final agreement text.** Owner 08/11/2026: Print Lease will print the lease agreement filled with the Lease's details, marked "Signed copy" with the signing date. The agreement text is still with the owner's lawyer, so the button is left out until the final text comes. Only "Print draft" for a draft Lease is in the app.
